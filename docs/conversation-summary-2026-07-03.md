# AI创新黑客松项目沟通总结（2026-07-03）

## 当前结论

1. 官网用户侧的核心标语统一为：`36小时 · 让想法落地，让创新发生`。
2. 观众端不需要单独的“投票”导航入口，作品展厅本身承担浏览与投票功能。
3. 评委端不需要看到组队入口，评委工作流聚焦在作品浏览与五维评分。
4. 组队人数显示应以真实后端成员为准，不能把静态占位头像计入满员判断。
5. 评委评分页左侧队伍卡的“浏览作品”入口应常驻显示，移动端进入卡片内容流，避免遮挡评分项。
6. 倒计时、路演计时需要以前后端同步状态为准，不能只做前端本地倒计时。

## 过程中遇到的问题

1. 需求表述有时是基于截图局部区域，我需要先定位这个区域对应的文件和数据来源，避免误改其他页面。
2. “取消投票页面”曾经被理解成取消作品展厅投票能力，后来澄清为取消顶部独立“投票”导航入口。
3. 评委页视觉验证时，真实后端接口曾因 MySQL 连接失败返回 500；这属于环境/后端连接问题，不是前端布局问题。
4. 工作区里存在多处既有未提交改动，同一个文件中可能同时包含本次修改和之前的功能修改，需要区分来源，避免误回滚。

## 后续建议

1. 对“角色可见导航”建立一张产品规则表：观众、选手、评委、管理员分别能看到哪些页面。
2. 对“作品状态”建立状态机文档：草稿、已提交、审核中、已发布、退回分别允许哪些操作。
3. 对“前后端同步时间”单独做一组验收用例：管理员启动、用户端刷新、用户端不刷新、后端重启四种情况都要覆盖。
4. 每次改动用户侧 `src/site.js` 后，同步更新 `site.html` 的 `?v=` 缓存版本号，避免浏览器继续加载旧脚本。
