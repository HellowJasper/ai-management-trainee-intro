# 线下黑客松上线前稳定性清单

时间：2026-07-05
活动目标：2026-07-08 线下黑客松作为管理系统使用，优先保证不出错。

## 当前结论

系统核心链路已经具备可用闭环：登录与角色分流、组队、作品提交、管理员审核发布、作品展厅、观众投票、评委评分、管理员锁分、最终结果发布。

当前优先级不应继续追求视觉出彩，而应切换到稳定性验收：确认真实用户、真实作品、真实投票、真实评分、真实发布流程能跑通。

## 关键术语

- 选手端：参赛选手使用的页面，主要负责组队、队伍工作台、作品提交。
- 作品工作台：队伍内部维护作品信息的页面，提交内容包括标题、介绍、技术标签、Demo 链接、代码地址、飞书作品页、展示截图。
- 作品展厅：观众、评委、管理员看到公开作品的页面，只展示管理员审核发布后的作品。
- 发布：管理员把作品状态改为 `published`，作品才进入公开展厅。
- 锁分：管理员确认所有评委评分完成后，将评分状态固定，后续用于最终结果计算。
- 快照：最终结果发布时生成的一份不可变结果记录，用于复核和追溯。

## 上线前必须演练

1. 登录与角色

- 用真实飞书账号登录。
- 检查选手、观众、评委、管理员四类角色是否进入正确界面。
- 确认普通观众看不到组队、评分、管理入口。
- 确认评委看不到组队入口，只能看作品展厅和评委评分。

2. 作品提交

- 选一支测试队伍，从选手端进入队伍工作台。
- 上传 1-2 张作品截图。
- 填写作品标题、一句话介绍、技术标签、飞书作品页链接。
- 点击提交作品。
- 管理员后台应能看到该作品进入待审核状态。

3. 作品发布与展厅

- 管理员将测试作品发布。
- 观众端作品展厅应出现该作品。
- 点击详情后，应能看到截图轮播、作品介绍、技术标签、团队成员和飞书作品页按钮。

4. 飞书文档

- 点击作品详情里的飞书作品页。
- 确认能打开真实飞书文档。
- 注意：系统只能打开链接，飞书文档本身还需要设置公司内可访问权限。

5. 投票

- 管理员开启投票窗口。
- 观众用真实账号投票。
- 确认同一个账号只能投一票。
- 确认取消投票、重新投票逻辑符合预期。
- 管理员关闭投票窗口后，观众不能继续投票或改票。

6. 评委评分

- 每个评委对所有已发布作品完成五维评分。
- 每项评分范围是 0-100。
- 正式提交后，评委不能重复修改。
- 管理员后台要能看到每位评委提交进度。

7. 最终结果

- 管理员关闭投票。
- 管理员确认所有评委完成评分。
- 管理员锁定评分。
- 管理员发布最终结果快照。
- 前台排行榜和大屏结果应读取发布后的快照。

## 当前最需要防的风险

1. 用户角色不完整

如果某个评委没有被设为评委，系统不会把他计入评分进度。活动前必须确认 8-9 位评委都在用户管理里是 `judge` 角色。

2. 飞书文档权限没开

作品详情页会渲染飞书文档链接，但能否打开取决于飞书文档本身权限。建议所有作品文档统一设置为公司内可访问。

3. 作品只提交未发布

选手提交后状态是 `submitted`，普通观众不会在作品展厅看到。管理员必须审核发布为 `published`。

4. 上传目录不是持久化

展示截图会保存到服务器 `assets/uploads/works/`。如果服务器部署会清空该目录，图片会丢。正式环境需要确认上传目录不会被部署覆盖。

5. 活动当天网络或内网不稳定

建议准备备用方案：导出用户表、队伍表、作品表、投票结果、评委评分表。关键阶段至少能人工核算。

## 活动当天建议

- 开场前 30 分钟，用管理员账号检查 API 连接、后台数据同步、当前阶段、倒计时状态。
- 组队阶段结束后，管理员锁定队伍，避免选手临时变动。
- 作品提交阶段结束后，管理员统一审核发布作品。
- 投票开始前，确认作品展厅中所有作品都能打开详情和飞书文档。
- 评分开始前，确认评委名单和已发布作品数量一致。
- 发布结果前，先截图或导出投票与评分数据，再点击最终发布。

## 判断标准

这次项目的最低成功标准不是视觉多惊艳，而是：

- 真实用户能登录；
- 选手能提交；
- 管理员能发布；
- 观众能投票；
- 评委能评分；
- 最终结果可计算、可解释、可复核。

只要这六条稳定，系统就能支撑线下活动。
